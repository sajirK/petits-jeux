# Les Petits Jeux — V2 : architecture et système de niveaux

> Branche locale `v2` (rien n'est publié tant que la V2 n'est pas validée).
>
> **État : les 36 jeux sont passés en V2** (kit, 3 niveaux ou jeu libre, vraie fin), testés par `npm test` et par le robot de bout en bout.

## 1. Audit de la V1 (mesuré, 36 jeux, iPad 768 px et téléphone 390 px)

| Constat | Détail |
|---|---|
| Niveaux | 15 jeux **sans niveaux**, 9 avec un niveau automatique « ◀ Niveau N ▶ » (3 à 6 niveaux selon le jeu), 5 avec des « modes », 1 avec un sélecteur de difficulté. **Aucune cohérence.** |
| Fin de partie | 31 jeux **tournent en boucle** sans écran de fin : l'enfant n'a jamais la satisfaction d'avoir « fini ». |
| Lecture | Trop de texte pour un non-lecteur : Que ferais-tu ? (40 mots), Mon jardin (38), Réflexe (29), Tour du monde (28), Saisons (23). |
| Cibles tactiles | Boutons de 37 à 43 px sur téléphone (J'écris, Boulangerie, Respire, Horloge, Saisons, Bulles, Piano). Minimum V2 : **64 px** (doigt de 5 ans). |
| Voix | Présente partout, mais formulée au cas par cas, sans bouton « réécouter la consigne » systématique ni relance quand l'enfant hésite. |
| Feedback | Confettis présents, mais pas de particules au point de contact, pas d'écran de victoire, erreurs signalées différemment selon les jeux. |
| Robustesse | Pas de page qui déborde, pas d'erreur JS. Anti-zoom partiel (meta + gestures), pas de verrou double-tap / appui long / pull-to-refresh partout. |

## 2. Principes V2

1. **Zéro lecture nécessaire** : chaque consigne est dite par la voix **et** montrée (icône, animation de la main 👆, objet qui pulse). Le texte est petit et secondaire.
2. **3 niveaux partout** : 🟢 Facile ⭐ · 🟡 Moyen ⭐⭐ · 🔴 Difficile ⭐⭐⭐. Facile par défaut, dernier niveau mémorisé par jeu.
3. **Des parties courtes avec une vraie fin** : une partie = une **manche** de 5 à 8 défis (ou un temps), puis un **écran de victoire** (1 à 3 étoiles, Plume qui danse, autocollant).
4. **Feedback immédiat et généreux** : son + particules au point touché + voix variée. L'erreur n'est jamais punitive (petit « boing », l'objet revient, indice).
5. **Le même squelette pour tous les jeux** : même barre du haut, mêmes boutons, mêmes gestes, mêmes écrans.

## 3. Architecture technique

Toujours **sans dépendance ni build** (HTML/CSS/JS, hébergeable tel quel), mais avec un vrai « kit » de composants partagés.

```
css/
  tokens.css        ← couleurs, rayons, ombres, espaces, typo, durées d'animation
  kit.css           ← composants : barre de jeu, boutons, sélecteur de niveau, écran de fin, consigne…
  common.css        ← (V1, gardé pendant la migration)
js/
  version.js        ← numéro de version + date + journal des changements
  common.js         ← (V1) sons, voix bas niveau, stockage, étoiles, autocollants
  kit/
    kit.js          ← point d'entrée : Kit.game({...})
    levels.js       ← système de niveaux standard (3 niveaux, mémorisés)
    voice.js        ← couche de voix : consigne, relance, encouragements, félicitations
    feedback.js     ← particules, réussite, erreur douce, célébration
    endscreen.js    ← écran de fin de manche (étoiles, Plume, rejouer, niveau suivant)
    drag.js         ← glisser-déposer robuste (zones de dépôt aimantées, retour animé)
    viewport.js     ← anti-zoom, anti appui-long, anti pull-to-refresh, bouton maison
games/<id>/
  index.html        ← la page du jeu : décrit ses 3 niveaux et ses manches
  logic.js          ← logique pure, testée (inchangé)
tests/              ← tests Node (logique + contenu + kit)
scripts/release.js  ← monte la version, met à jour le journal, crée le tag git
```

### Le contrat d'un jeu V2

Chaque jeu se déclare en une fois ; le kit fournit tout le reste (barre, niveaux, voix, progression, fin) :

```js
Kit.game({
  id: "couleurs",
  title: "Les Couleurs", icon: "🌈",
  instruction: (lv) => "Touche le ballon de la bonne couleur !",   // dite à l'ouverture et sur 🔊
  levels: {                                                         // ce qui change selon le niveau
    1: { colors: 3, rounds: 5 },
    2: { colors: 4, rounds: 6 },
    3: { colors: 6, rounds: 8 },
  },
  start(level, round) { /* construit le défi */ },
});
// dans le jeu :  round.win(el)  /  round.miss(el, "indice")  →  le kit gère sons, particules, voix,
// étoiles, barre de progression, et l'écran de fin quand la manche est finie.
```

## 4. Système de niveaux standard

| | 🟢 Facile | 🟡 Moyen | 🔴 Difficile |
|---|---|---|---|
| Étoiles | ⭐ | ⭐⭐ | ⭐⭐⭐ |
| Pour qui | 3-4 ans, découverte | 5 ans | 6-7 ans |
| Principe | peu de choix, aides visibles, pas de temps | choix normaux, aide à la demande | plus de choix, pièges, parfois du temps |

- **Sélecteur** : 3 grosses pastilles colorées (sans texte nécessaire), toujours au même endroit, voix « Facile », « Moyen », « Difficile ».
- **Mémoire** : `jeux.<id>.niveau` (1, 2 ou 3), Facile par défaut. Les anciens niveaux V1 sont convertis.
- **Proposition, pas imposition** : après une manche à 3 étoiles, Plume propose « Tu veux essayer plus difficile ? » (gros bouton). On ne change jamais le niveau tout seul.
- **Résultat d'une manche** : ⭐⭐⭐ sans erreur · ⭐⭐ 1-2 erreurs · ⭐ au-delà (on gagne toujours au moins une étoile).

## 5. Versionnage

- `js/version.js` : `{ version: "2.0.0", date: "…", notes: [...] }`, affiché en bas de l'accueil (« v2.0.0 · 22/11/2026 ») et dans la console.
- Version **sémantique** : `2.1.0` = nouveaux jeux, `2.0.1` = corrections.
- `CHANGELOG.md` tenu à jour ; chaque publication = un **tag git** `v2.0.0`.
- Les fichiers CSS/JS sont chargés avec `?v=2.0.0` : après une publication, les iPad prennent bien la nouvelle version (plus de vieux cache).
- `npm run release -- 2.1.0 "Ajoute le jeu des rimes"` fait tout d'un coup.
